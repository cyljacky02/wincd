# Release integrity policy

This repository distributes WinCD runtime packages independently of development history.

## Candidate and publication

1. Select an exact source revision and version in the private development process.
2. Build a runtime package once and validate that candidate. Keep its source-to-package mapping and validation evidence privately.
3. Review a GitHub Release draft containing the unchanged package, SHA-256 checksum, public-safe release notes, and required license notices.
4. Publish only after licensing and release review are complete. Use a pre-release designation while acceptance remains incomplete.

The first runtime release has not yet been published. A version label or a pre-release flag is not proof that every platform or operational scenario has been validated.

## Download integrity

Use the named runtime ZIP, not GitHub's autogenerated source archives. Compare its SHA-256 with the matching `SHA256SUMS` entry from that release before extraction.

Repository release immutability is enabled before the first publication. Once an immutable release is published, its attached files cannot be added, replaced, or removed in place. Corrections require a new package version and release, rather than overwriting a previous download. Release notes can still be corrected without changing package bytes.

Checksums identify exact package bytes. They do not conceal the readable runtime scripts, guarantee vulnerability-free code, or independently establish publisher identity. No WinCD Authenticode signature or private-build provenance attestation is promised for the first candidate.

GitHub's destination release tag identifies this distribution repository's documentation commit, not a commit in a different development repository.

## Safe public content

Runtime packages and public notes must not contain real Deployment Profiles, credentials, private deployment content, logs, or unreviewed internal metadata. Third-party licenses remain applicable and their required notices must be retained.
